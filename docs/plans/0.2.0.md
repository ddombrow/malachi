# Code Mode (0.2.0), then local MCP (0.3.0)

malachi is "Pi with more guardrails". Pi 1.0 added Code Mode (the model
writes a short script that calls tools) and MCP. Both come to malachi, in
that order, and neither may widen what the user's sandbox policy allows.

## Code Mode (0.2.0)

One new tool, `script`, runs a short JavaScript program. Inside it every
malachi tool is a function, and only what the script prints or returns goes
back to the model.

```js
const [mod, hits] = await Promise.all([
  tools.read({ path: "go.mod" }),
  tools.grep({ pattern: "TODO", output: "files" }),
]);
return hits.text.split("\n").filter(f => f.endsWith(".go")).join("\n");
```

Why, without MCP: fewer round trips (an exploration streak of read/grep turns
becomes one or two scripts, each turn having resent the whole context),
less noise (a script returns the 6 lines that matter, not 200), and
multi-file edits in one call. It adds nothing to trust: the script can only
act through tools that are already confined.

### Engine

- **QuickJS-ng compiled to WASI** (wasm32-wasi, built with `zig cc`), run
  under **wazero**: pure Go, no cgo. Our own build and a thin C glue file;
  no quickjs-libc, so no `std`/`os` modules, no filesystem, network,
  environment or timers inside the guest.
- **Imports the guest gets:** one host function that runs a batch of tool
  calls, output, and a clock. Nothing else.
- **The `.wasm` is committed**, with `task wasm` to rebuild it from a pinned
  QuickJS-ng source.
- **Limits:** `JS_SetMemoryLimit` plus the wasm page cap (256 MB); an
  interrupt handler and context cancellation for Esc and timeouts;
  wazero's compilation cache, so a script starts in milliseconds after the
  first.

### Batching

QuickJS is single-threaded, but scripts use `Promise.all`:

- `tools.x(args)` records the call and returns a pending promise.
- When the job queue is empty and calls are pending, the glue hands them all
  to Go in one batch.
- Go runs the batch like a turn's tool calls: `Parallel` tools together,
  others one at a time, results resolving promises in call order.

### The tool (`codemode/`, wired in `coding`)

- `codemode.NewTool(tools, opts) *agent.Tool`; `codemode` imports `agent`
  only, so Samson and other harnesses can use it.
- Every call goes through the normal tool path: sandbox checks, hooks,
  `sandbox_denied` logging. A script can do nothing the model couldn't do
  one call at a time.
- Results reach scripts as `{text, details, isError}`; a failed call is a
  value, not a crash.
- `searchTools(query)`, `describeTool(name)`, `ALL_TOOLS` (Pi's API), ready
  for MCP's deferred tools.
- Limits: timeout (bash's default), output cap with a spill file, a maximum
  number of calls per script.
- Auditing: the calls a script made are in its result's details; the TUI
  shows them as progress, not as transcript messages.
- Measurement: scripts, calls per script and errors go to the diagnostics
  log, to judge after a few weeks whether it pays off.

### Network: a `fetch` tool, not an engine capability

Scripts get the network through a tool, never through the engine. A `fetch`
host function inside the guest would be a second way out, beside hooks,
the sandbox, the network toggle and denial logging, and every guard would
need a twin; the engine's import list (checked by `TestImports`) stays
free of effects. So `fetch` is an ordinary tool in `coding`, called
directly or as `tools.fetch({url})` from a script (several at once under
`Promise.all`, with no engine change).

- **The network toggle governs it.** Off means refused, as for bash. The
  risk is exfiltration (a script reads files, then posts them), so whether
  that is possible stays the user's decision, never the model's.
- **Finer than the OS sandbox can be.** Seatbelt and Landlock see network
  on or off (Landlock at best a port); the tool sees each request:
  - an optional host allowlist in settings;
  - loopback, private, link-local and metadata addresses
    (`169.254.169.254`) refused, checked on the resolved address at dial
    time so DNS can't point a name at them;
  - redirects checked by the same rules.
- **The usual caps:** response size, timeout, spill file for large bodies,
  HTML reduced to text. Fetched text is untrusted input.
- **Audited:** the method and URL of every request in the result's
  details, so a script's network use shows in its call list.

### Steps

1. Engine: QuickJS-ng WASI build, glue, wazero host, batching loop, limits.
   Done when a test script runs three fake tools concurrently and a runaway
   loop is killed. (Done: 6ec729e.)
2. `script` tool in `coding`: real tools, caps, spill files, call limit,
   details. (Done.)
3. `fetch` tool: network toggle, address and host rules, caps, details.
   (Done.)
4. TUI progress for a script's calls, a Code Mode section in the sidebar,
   RPC state. (Done.)
5. Release 0.2.0.

## Local MCP (0.3.0)

An MCP server is treated as a long-running command, under the same rules as
bash.

1. **Local only.** malachi starts servers over stdio itself and never
   connects to an HTTP server, remote or on localhost: a process someone
   else started is one malachi cannot confine.
2. **Sandboxed like bash, plus the server's own roots.** Each server runs
   under the session's policy (hidden paths, private home, network, Unix
   sockets) plus readable and writable roots declared for it in
   `mcp.json`. Those roots apply to the server's process only, never to
   bash or the file tools; the model reaches that data only through the
   server's tools. The command's own directory is readable automatically.
   No server may opt out of the sandbox.
3. **The network toggle covers servers.** With the network off, servers are
   offline too. A network-backed server works when the user turns the
   network on, the same exposure as `gh` with the network on. Per-server
   network grants could come later, as an explicit user setting.
4. **Policy changes restart servers.** An OS sandbox is fixed when a
   process starts, so toggling the network or adding roots restarts
   running servers on their next use; the sidebar says so.
5. **Configuration:** `~/.malachi/mcp.json` only, in the common
   `mcpServers` shape. Servers get the minimal command environment plus
   only the variables their entry names, never malachi's keys. An optional
   `tools` allowlist per server. No project `.mcp.json` in 0.3.0: that
   would run code from the repository.

```json
{
  "mcpServers": {
    "malachi-scripture": {
      "command": "~/src/malachi-scripture/bin/ner",
      "args": ["-data", "~/src/malachi-scripture/data"],
      "readable": ["~/src/malachi-scripture"],
      "writable": ["~/src/malachi-scripture/data"]
    }
  }
}
```

### Design

- `mcp/` package: a hand-written JSON-RPC 2.0 client over stdio
  (initialize, `tools/list` with pagination and `listChanged`,
  `tools/call`), results mapped to `agent.ToolResult`. Imports `agent` only.
- **Deferred tools:** one line per server in the system prompt, no schemas;
  the model finds and calls MCP tools from Code Mode scripts
  (`searchTools`, `describeTool`, `tools.mcp__server__tool`). A server can
  set `"deferred": false` to expose its tools directly.
- Servers start in the background; a slow or broken server never blocks a
  session.
- Frontends: an MCP section in the sidebar (each server's status, tool
  count, roots), `/mcp`, `mcp` in RPC `get_state` and an `mcp_changed`
  event.

### Required before shipping

- **Server environments on Linux.** A sandboxed command can read a
  same-user process's `/proc/<pid>/environ`, so a token in a server's
  environment would be readable from bash. malachi protects its own process
  (`ProtectProcess`); servers need the same protection, or tokens passed
  another way. macOS's profile already denies process inspection.

### Known fits

- **malachi-scripture:** stdio, pure Go, no network. Needs its repository
  readable and `data/` writable (notes, SQLite WAL files).
- **apple-health-dash:** needs a stdio entry point first (`cmd/ahealth-mcp`
  running `mcpserver.New` over `mcp.StdioTransport`), then `data/`
  writable for DuckDB and its writing tools. Works on a local copy of the
  database; production is remote, so out of reach by design.
